# レシピクラフト作成の仕様

本ゲームにおける「ラーメンレシピの作成」は、プレイヤーが構成要素を組み合わせて、じぶんの「理想の一杯 」を組み立てるクラフト要素である。
最終的には10個の評価軸により内部数値化され、お客ごとの評価を産み出す。

## レシピの構成要素

* 麺
* スープ
* かえし (タレ)
* 香味油
* 具材 (主役・補助)
* 盛り付け (器・配置)

## 評価軸のリスト

## 評価値の算出ロジック

本ゲームにおいて、ラーメン一杯の「味の評価」は、以下の手順で10軸の数値評価として内部的に算出されます。この評価は、プレイヤーには直接数値としては表示されず、味の印象や顧客の反応などテキストベースで間接的に伝えられます。

### ステップ1: 構成要素ごとの評価寄与値の定義

各レシピ構成要素（例：スープ、香味油、具材など）は、作成時に10の評価軸に対する「寄与値（contribution）」が個別に算出されます。たとえばプレイヤーが「黒マー油」を香味油として自作した場合、その素材や調理法に応じて「香りの強さ」や「脂の量」などへの寄与度が即時に決定されます。

この寄与値は、ゲーム内で定義された各素材・工程のパラメータをもとに内部的に演算され、同じ名前の構成要素であっても、作り方が異なれば寄与値が変わる可能性があります。
たとえば「黒マー油」は「香りの強さ」や「脂の量」に強く影響するといった形で設定されます。

### ステップ2: レシピ全体のスコア集計

プレイヤーが選択したすべての構成要素について、対応する評価軸への寄与値を加算します。これにより、ラーメン一杯としての総合評価が10軸で求まります。各軸の値は0〜65535のuint16範囲でクリップされます。

### ステップ3: 特殊軸の補正計算

一部の評価軸は、単純加算ではなく相互補正を含みます。

* 「調和性」：全軸の偏差や相関性、過不足の少なさをもとに算出（ばらつきが少ないほど高評価）
* 「個性・創作性」：レア素材の使用、有機的でない組み合わせ、奇抜な盛り付けなどを元にスコアリング（現実性との距離が大きいほど高評価）

さらに、調理を担当する店員のスキルや経験値に応じて、全体の評価に対する補正が適用されます。具体的には、店員の「調理技術」パラメータに応じて、

* 評価軸ごとのスコアに微量なブーストを加える
* 調和性のブレを減少させる
* 個性の暴走を抑える（奇抜すぎて破綻している構成をマイルドに）

といった効果が発動します。これにより、同じレシピであっても、誰が調理するかによって仕上がりの評価が変わるようになります。全軸の偏差や相関性、過不足の少なさをもとに算出（ばらつきが少ないほど高評価）

### ステップ4: 顧客との嗜好マッチング

各顧客には10軸の「嗜好ベクトル（H）」が存在し、それぞれの軸について「重みベクトル（W）」も保持しています。この重みは、顧客がどの評価軸を重視するかを示すもので、嗜好ベクトルと完成したラーメンの評価ベクトル（R）との乖離に対してスコアへの影響度を調整します。

満足度スコア（S）は以下のように算出されます：

`S = Σ［w_i × (65535 - |r_i - h_i|)］（i = 1〜10）`

この仕組みにより、同じラーメンであっても「見た目重視の顧客」や「脂好きな顧客」など、各顧客の価値観に応じて評価結果が変動するリアリティのある嗜好評価が実現されます。

各顧客には10軸の「嗜好ベクトル（H）」が存在し、それぞれの軸について「重みベクトル（W）」も保持しています。この重みは、顧客がどの評価軸を重視するかを示すもので、嗜好ベクトルと完成したラーメンの評価ベクトル（R）との乖離に対してスコアへの影響度を調整します。

満足度スコア（S）は以下のように算出されます：

`S = Σ［w_i × (65535 - |r_i - h_i|)］（i = 1〜10）`

この仕組みにより、同じラーメンであっても「見た目重視の顧客」や「脂好きな顧客」など、各顧客の価値観に応じて評価結果が変動するリアリティのある嗜好評価が実現されます。各顧客には10軸の「嗜好ベクトル」が存在します。ラーメンの評価値と顧客の嗜好ベクトルとの乖離（差分）を算出し、最終的な「満足度」や「リピート率」として反映されます。すべての構成要素の引数を合計して各軸の終値を決定

* 軸同士の範囲は 0 〜 65535
* 調和性は「軸同士の偏差」の小さや互換性の高さで決定
* 個性は「使用素材の現実性や簡便さ」から不自然さを評価

## 評価値の算出例

以下に、評価ロジックに基づいて実際にラーメンと顧客の嗜好がどのようにマッチングされるかを示す例を記述します。

### ラーメン例

* 名称：黒香味油の濃厚鶏白湯
* 構成：
  * 高加水太麺
  * 鶏白湯スープ
  * 濃口醤油だれ
  * 黒マー油（香味油）
  * 具材：炙りチャーシュー、味玉、青ネギ
  * 盛り付け：黒どんぶり、放射状配置

### 顧客カテゴリ例

* カテゴリ名：男子大学生
* 嗜好傾向：
  * 脂の量：重視（w = 高）
  * ボリューム感：重視（w = 高）
  * 刺激・辛味：やや重視
  * 見た目の美しさ：軽視（w = 低）
  * 調和性：軽視

このような構成において、レシピが脂・ボリューム・刺激性に強く寄与していれば、評価軸とのマッチングにより高い満足度スコアが得られます。反対に、盛り付け重視の顧客ではこのラーメンは低評価となる可能性があります。

### ラーメン評価値の算出 (調理などの補正後)

以下は、店員の「調理技術」による補正を受けた後の、ラーメンの総合評価値です。調理技術は各評価軸に対して+3%のブースト補正を与えるものとし、調和性に対してはさらに安定化補正（+5%）が加えられた結果です。

| 評価軸               | 合計値（補正前） | 補正係数 | 合計値（補正後） |
|----------------------|------------------|----------|------------------|
| 旨味強度             |            35000 |    ×1.03 |            36050 |
| 香りの強さ           |            17000 |    ×1.03 |            17510 |
| 塩味の強さ           |            17000 |    ×1.03 |            17510 |
| 脂の量（こってり感） |            32000 |    ×1.03 |            32960 |
| 甘味の存在感         |             8000 |    ×1.03 |             8240 |
| 刺激・辛味           |             3500 |    ×1.03 |             3605 |
| 個性・創作性         |             9000 |    ×1.03 |             9270 |
| 見た目の美しさ       |            12500 |    ×1.03 |            12875 |
| ボリューム感         |            12000 |    ×1.03 |            12360 |
| 調和性               |            27000 |    ×1.08 |            29160 |

この補正により、同じレシピでも、調理スキルの高い店員が担当することで味の評価が全体的に底上げされ、顧客満足度が向上する設計となっています。

* 各評価軸における差分 = |ラーメン評価値 − 顧客理想値| を取り、重みを掛けた加重差分を合計。
* 評価スコア = 100 − (加重差分合計 / 正規化定数) ※正規化定数はゲームバランスに応じて決定（例：100000 など）
* 計算例（概略）：
  * 旨味強度差分：|36050 − 40000| × 1.0 = 3950
  * 脂の量差分：|32960 − 35000| × 1.2 = 2448
  * ボリューム感差分：|12360 − 14000| × 1.0 = 1640
  * ...以下同様に計算し、合計：例えば 12000 程度

→ 評価スコア ≒ 100 − (12000 / 100000) = 88.0

このように、個別の顧客カテゴリごとの嗜好と重みが評価に影響し、プレイヤーの戦略が顧客層に適合していれば高評価を得られる設計となっている。
