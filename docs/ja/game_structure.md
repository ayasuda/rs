# ゲーム全体構造：ラーメン屋シミュレーター

本ドキュメントは、本作「ラーメン屋シミュレーター」におけるシステム構成・プレイフロー・要素間の関係性を整理するものである。開発・実装・仕様拡張のベースとして参照される。

---

## 1. プレイ全体の流れ（基本サイクル）

```text
1. 店舗選定（立地・物件）→
2. レシピ作成（クラフト）→
3. 開店・営業（営業時間・顧客来店）→
4. 調理・提供（ミニゲームまたは自動）→
5. 評価（顧客ごとの嗜好ベクトル）→
6. 売上計算（価格×来客数）→
7. 改良（レシピ／内装／価格など）
　↓
（以降、日送りで繰り返し）
```

## 2. 主なシステム構成

| システム名    | 概要・役割                                 |
| -------- | ------------------------------------- |
| レシピクラフト  | 麺・スープなどを組み合わせ、10軸の評価ベクトルを生成           |
| 顧客評価システム | 顧客ごとの嗜好ベクトルとマッチングし、満足度・再来店を決定         |
| 店舗運営管理   | 立地、営業時間、内装、固定費、収支管理など。店舗ごとに戦略的選択を許容   |
| 来客数ロジック  | 評判・天候・時間帯などの補正により、カテゴリ別流入を算出          |
| メニュー設定   | 原価ベースの自動計算＋価格設定により利益率をコントロール          |
| 接客ミニゲーム  | タップ・スワイプで注文受付や提供を行うアクション要素（精度によって報酬差） |
| 評価→評判連動  | 高評価ラーメンの提供によりカテゴリ別評判スコアが上昇、流入率増加へ繋がる  |
| 顧客プロファイル | 来店時間帯／嗜好／満腹度／価格感度を持つ、10カテゴリに分類        |


## 3. 日送り・経営ループ構造
1日単位で営業・評価・利益計算を行い、任意タイミングで改良を挟む。

[営業開始]
 ↓
顧客来店（時間帯ごと）
 ↓
注文・調理（ミニゲームor自動）
 ↓
評価（顧客ごと）
 ↓
集計（評判・売上・来客履歴）
 ↓
[営業終了]
 ↓
報酬・改善フェーズ（新レシピ／価格変更／営業時間調整など）

## 4. 構成要素間の関係図（簡易）

```
[レシピ] ─→ [評価ベクトル] ─→ [顧客満足度] ─→ [評判スコア]
　　 ↓　　　　　　　                         ↓　　　　
[原価計算]　         　　　　　   　[価格戦略] ─→ [売上]
　　　　　　　　　　                        ↓
　　　　　[満腹度／予算制約] ──→ [サイドメニュー売上]
```

## 5. 補足：ゲーム内の主要な反復軸

| 軸     | 内容                           |
| ----- | ---------------------------- |
| 評価軸   | 顧客の満足度向上（味の適合）→評判UP→来客数UP    |
| 経営軸   | 営業時間／立地／価格などで収益改善            |
| 改良軸   | 評価結果や来客分析をもとにレシピ・内装・サービスを調整  |
| 顧客攻略軸 | 各カテゴリへの適応（時間帯／好み）による常連化・売上増加 |
