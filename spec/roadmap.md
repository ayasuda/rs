# 開発ロードマップ：ラーメン屋シミュレーター

本ドキュメントは、「ラーメン屋シミュレーター」の開発をどの順番で進めるかを整理したものである。

## 進め方

- **反復型で進める。** 1回のイテレーションで1つのまとまりを仕上げ、遊んで確かめてから次へ進む。
- **日付は決めない。** 各イテレーションには目安の工数（実際に手を動かす日数）だけを置く。個人開発なので、いつ終わるかは約束しない。
- **最初に仮実装で一周させ、あとから作り込む。** 第1イテレーションでゲームループ全体を仮の形で通し、第2イテレーション以降で機能ごとに作り込む。
- **作り込みに時間を使う。** これはゲームなので、動くだけでは足りない。各イテレーションの工数の半分程度は、手触り・見た目・文言・音といった細部に充てる前提で見積もっている。
- **イテレーションごとに小さなシミュレータを作る。** そのイテレーションで触る数値を、画面を通さずにまとめて回して確かめる道具を用意する。ゲーム本体と同じコードを Godot のヘッドレス実行で動かし、ロジックを二重に持たない。

### イテレーションの完了条件（共通）

1. 対象の機能が仕様書どおりに動き、仕様書の側も実装に合わせて更新されている
2. そのイテレーションのシミュレータで、数値が狙った範囲に収まっていることを確かめた
3. 対象の画面が、仮の見た目ではなく製品として出せる見た目・手触りになっている
4. 最初から通しで遊んで、前より面白くなっている

---

## 第1イテレーション：仮実装でゲームループを一周する（完了）

店舗選び → レシピ作成 → 営業 → 評価 → 売上 → 改良、を仮の形で最後まで通す。現在の `game/`（Godot 版）がこれにあたる。

| タスク | 状態 | 説明 |
| --- | --- | --- |
| レシピ作成 | 済 | 用意された素材を組み合わせ、10軸の評価ベクトルを算出 |
| 顧客評価 | 済 | 10カテゴリの嗜好・重みとの照合、満足度、感想テキスト |
| 店舗経営 | 済 | 立地選択、営業時間と固定費、価格設定、サイドメニュー |
| 来客と評判 | 済 | 評判 → 流入率 → 来客数の連鎖、天候・曜日・宣伝・内装の補正 |
| 日送り | 済 | 1日単位の営業シミュレーションと結果表示 |
| 接客ミニゲーム | 済（暫定） | タイミングを合わせるだけの簡易版 |
| セーブ・ロード | 済 | オートセーブと再開 |

- **シミュレータ**：各立地で初期レシピのまま30日営業し、収支と評判の推移を出す（`game/tests/balance_report.gd`）
- **仮のままのもの**：数値全般、文字とボタンだけの画面、素材は選ぶだけ、ミニゲームの仕様

## 第2イテレーション：レシピクラフトの作り込み

ゲームの核。「理想の一杯を組み立てる」こと自体が楽しくなるまで作り込む。

| タスク | 説明 |
| --- | --- |
| 特殊軸の補正 | 調和性を軸のばらつきから、創作性を組み合わせの珍しさから算出する |
| 構成要素の自作 | 自家製麺・自家製スープ・かえし・香味油をパラメータ指定で作る（シーン C1〜C20） |
| 仕入れ品との使い分け | 製麺所・業務用スープなど、自作との差と選ぶ理由を作る |
| レシピノートの表現 | ラーメン屋のメモ帳として見せる。一覧・詳細・編集の手触り |
| 味の伝え方 | 数値を見せずに味の印象を伝える文言と、ラーメンの見た目 |

- **シミュレータ**：作れるレシピを総当たりし、顧客カテゴリごとの満足度の分布を出す。どの客層にも勝つ一杯や、誰にも刺さらない素材が無いことを確かめる
- **目安の工数**：20〜30日

---

## 第3イテレーション：顧客と評判の作り込み

「誰に向けて作るか」を考える面白さを作る。

| タスク | 説明 |
| --- | --- |
| 顧客プロファイルの確定 | 嗜好・重み・予算・満腹度・生活リズムを10カテゴリ分、根拠を持って決める |
| 常連化 | 高評価を続けると常連になる仕組みと、その見返り |
| 感想と表情 | 満足度に応じたセリフのバリエーション、表情、来店時の演出 |
| 顧客分析・評判分析 | 何が受けて何が外れたかを読み取れる画面（シーン E1・E2） |

- **シミュレータ**：レシピと価格を固定して長期間（100日程度）営業し、カテゴリ別の評判・来客・常連数の推移を出す。評判が上がりきる／下がりきるまでの日数を確かめる
- **目安の工数**：15〜25日

---

## 第4イテレーション：店舗経営の作り込み

「どう稼ぐか」の選択肢に、それぞれ勝ち筋がある状態にする。

| タスク | 説明 |
| --- | --- |
| 立地・物件 | 物件ごとの個性、契約・移転の判断材料（シーン G1・G2） |
| 内装・設備 | 清潔感・装飾・看板・座席を個別に調整する（シーン G3） |
| メニュー・価格戦略 | トッピングのオプション販売、サイドメニューの構成、価格の効き方 |
| 店員の育成・管理 | 複数の店員、スキル成長、担当の割り当て（シーン E3） |
| 資金繰り | 序盤の資金、倒産の条件、立て直しの余地 |

- **シミュレータ**：「低価格で数を取る」「高単価で利益を取る」「深夜特化」など、決め打ちの方針をいくつか用意して同じ日数回し、収支を並べて比べる。一つの方針だけが突出しないことを確かめる
- **目安の工数**：20〜30日

---

## 第5イテレーション：営業の演出とミニゲーム

一番長く眺める場面。営業中の時間そのものを楽しくする。

| タスク | 説明 |
| --- | --- |
| 接客ミニゲームの仕様確定 | 注文受付 → 調理 → 提供の操作と、おまかせとの差（精度ボーナス） |
| 営業シーンの見せ方 | 来店から退店までを眺めて楽しい形にする（シーン D2） |
| 結果の見せ方 | 売上・評判・感想を、次の一手を考えたくなる形で出す（シーン D4） |
| 絵と音 | 営業まわりのイラスト・アニメーション・効果音・BGM |

- **シミュレータ**：上手さの違う仮想プレイヤー（入力のズレ幅を変えたもの）にミニゲームを繰り返し遊ばせ、得点の分布と、おまかせとの報酬差を出す。下手でも損をしすぎず、上手ければ報われることを確かめる
- **目安の工数**：25〜40日

---

## 第6イテレーション：通しの体験

個々の機能ではなく、最初の1時間と、その先の遊び続ける理由を作る。

| タスク | 説明 |
| --- | --- |
| チュートリアル | 初回プレイの導入（シーン F1） |
| ガイドブック | 仕組みと用語のヘルプ（シーン F2） |
| 進行のテンポ | 素材・立地・機能が解放されていく順番と速さ |
| 設定・データ管理 | 音量・演出・セーブデータの管理（シーン A3・A4） |
| 全画面の統一感 | 画面ごとの見た目・文言・操作の揃え直し |

- **シミュレータ**：単純な方針で自動プレイするボットに開始から数十日遊ばせ、所持金・評判・解放状況の進み方を出す。序盤で詰まる、または早々にやることが無くなる、を見つける
- **目安の工数**：15〜20日

## 第7イテレーション：リリース準備

| タスク | 説明 |
| --- | --- |
| 実機対応 | iOS / Android への書き出し、画面サイズ・ノッチ・操作感の確認 |
| フォント・素材の同梱 | 日本語フォントとライセンスの確認 |
| セーブデータの互換 | バージョンが上がっても続きから遊べるようにする |
| 不具合修正・最終調整 | 通しプレイによる問題の洗い出しとパラメータの最終調整 |
| ストア申請素材 | アイコン・説明文・スクリーンショット |

- **シミュレータ**：これまでのシミュレータを乱数固定でまとめて回し、結果が前回から変わっていないことを確かめる回帰チェック。最終調整で意図しない所が動いていないかを見る
- **目安の工数**：10〜15日
